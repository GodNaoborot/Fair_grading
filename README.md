# Fair grading

**Насколько справедлива оценка студента — и сколько в ней от него самого, а сколько от предмета?**

Средний балл сравнивает студентов, которые учились на разных предметах, как будто
предметы одинаковые. Пятёрка по предмету, где пятёрки у всех, и четвёрка там, где
почти все получили три, — в среднем балле весят одинаково. Этот проект разделяет
два вклада.

Байесовская модель в духе IRT (Item Response Theory) оценивает по матрице оценок
две скрытые величины:

- **способность студента** `s ∈ [0, 1]` — одна на студента,
- **сложность предмета** `d ∈ [0, 1]` — одна на предмет,

так, чтобы вероятности оценок 2–5 в каждой ячейке лучше всего объясняли
наблюдаемые данные. На выходе — не число, а **апостериорное распределение**:
видно не только «сколько», но и «насколько мы в этом уверены».

```
              data/grades_sem*.csv        138 студентов × 6 и 10 предметов
                        │
          compute_chi_priors.py           приор сложности из формы
                        │                 распределения оценок
            run_mcmc_chi_prior.py         NUTS, 12 трасс
                        │
    ┌─────────────┬─────┴───────┬─────────────────┐
diagnostics.py validate.py  query.py    plot_ratio_comparison.py
r_hat / ESS    LOO + PPC    ответ по    графики сравнения
дивергенции    какая лучше  студенту    трёх формул ratio
                            и предмету
```

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

```bash
python scripts/compute_chi_priors.py    # приоры сложности    -> data/chi_priors.json
python scripts/run_mcmc_chi_prior.py    # MCMC, 12 трасс      -> results/traces/*.nc
python scripts/diagnostics.py           # сходимость          -> results/diagnostics.csv
python scripts/validate.py              # LOO + PPC           -> results/loo_compare_*.csv
```

Уже посчитанные трассы переиспользуются, так что повторный запуск ничего не
пересчитывает. Полезные ключи: `--quick` (черновые настройки для проверки
пайплайна), `--sem 1`, `--ratio sigmoid`, `--model nocond` — считать только
нужную часть.

### Сэмплер

По умолчанию используется **nutpie** (`--sampler nutpie`) — реализация NUTS,
компилирующая модель через numba. Это не украшение: у родного бэкенда PyTensor
на машине без C++-компилятора (типичная ситуация на Windows) граф выполняется
интерпретатором Python, и одна трасса не досчитывается за десять минут. С nutpie
та же трасса занимает порядка полуминуты. Переключиться на родной бэкенд
можно через `--sampler pymc`.

## Главное: запросы к модели

Что можно спросить после того, как трассы посчитаны:

```bash
# Что вообще есть в данных
python scripts/query.py --sem 1 --list

# Способность студента + прогноз по каждому его предмету
python scripts/query.py --sem 1 --student 42

# Сложность предмета + фактическое распределение оценок
python scripts/query.py --sem 1 --subject "Математический анализ"

# Конкретная пара: какую оценку модель ожидала и что вышло на самом деле
python scripts/query.py --sem 1 --student 42 --subject "Высшая алгебра" --plot
```

Реальный вывод для пары:

```

Студент #42
-----------
  способность s : 0.354 ± 0.087   94% HDI [0.197, 0.519]

Предмет «Высшая алгебра»
------------------------
  сложность d   : 0.409 ± 0.027   94% HDI [0.358, 0.459]

Студент #42 × «Высшая алгебра»
------------------------------
             P факт
оценка
2       0.1232
3       0.4683  <--
4       0.3685
5       0.0400

  E[оценка] = 3.33
  фактическая оценка = 3, модель давала ей P = 0.468
```

Распределение оценки считается маргинализацией по всем выборкам `(s, d)` из
трассы, а не подстановкой средних — поэтому неопределённость в `s` и `d`
честно переносится в прогноз.

Ключи: `--model cond|nocond` (с гейтом крайних оценок или без),
`--ratio legacy_sd|current|sigmoid` (формула совпадения), `--plot` (сохранить график).

**Дефолт — `nocond` + `sigmoid`**: лучшая предсказательная способность на
этих данных при корректной семантике. Обоснование — в разделе «Валидация».
Остальные комбинации никуда не делись: MCMC считает все 3 × 2, любую можно
запросить ключами.

## Модель

Для каждой наблюдаемой пары (студент `i`, предмет `j`) считается скаляр
«совпадения» `r ∈ [0, 1]`, а из него — вероятности четырёх оценок.

**Приоры.** `s ~ Beta(2, 2)`; `d ~ Beta(α_j, β_j)`, где центр приора для каждого
предмета берётся из chi-square оценки (см. ниже), а концентрация фиксирована
`α + β = 4` — та же «сила», что у `Beta(2, 2)`.

**Совпадение.** Три взаимозаменяемые формулы, выбираются параметром `ratio_kind`:

| вариант | формула | свойство |
|---|---|---|
| `legacy_sd` | `s / (s + d)` | симметрична, при `s = d` даёт ровно ½ |
| `current` | `1 − d(1 − s)` | асимметрична: равна 1 и при `d = 0`, и при `s = 1` |
| `sigmoid` | `σ(k(s − d))`, `k = 5` | симметрична, гладкая, резкость регулируется `k` |

**Правдоподобие.** Вероятности оценок — семейство, нормированное по построению
(`f_2 + f_3 + f_4 + f_5 ≡ 1`, отдельная нормировка не нужна):

```
f_2(x) = (1−x)³ / ((1−x)³ + 10x²)      f_5(x) = f_2(1 − x)
f_3(x) = (1−x) · (1 − f_2(x) − f_5(x)) f_4(x) = f_3(1 − x)
```

Оценка ~ `Categorical(f_2(r), f_3(r), f_4(r), f_5(r))`.

**Два варианта модели.** `nocond` — вероятности целиком задаются `f_2..f_5`.
`cond` — сверху добавлен «гейт»: две сигмоиды в координатах `ratio`,
подталкивающие уверенные случаи к 2 и 5. Итоговое распределение — смесь

```
P = p_5 · [0.001, 0.001, 0.001, 0.997]
  + p_2 · [0.997, 0.001, 0.001, 0.001]
  + (1 − p_5 − p_2) · [f_2(r), f_3(r), f_4(r), f_5(r)]
```

где `p_5 = σ(t(r − hi))`, `p_2 = σ(t(lo − r))`.

**По умолчанию `lo = 0.3`, `hi = 0.7`, `t = 15`** — пороги сдвинуты внутрь
шкалы намеренно. При «естественных» `0.1 / 0.9` гейт срабатывает только там,
где `f`-функции и без него дают 0.997, то есть `cond` становится
неотличима от `nocond`. Эффект текущих порогов:

| сценарий | `nocond` | `cond` (0.3 / 0.7) |
|---|---|---|
| хороший студент, средний предмет | E = 4.17 | E = 4.67 |
| средний, средний | E = 3.50 | E = 3.50 |
| слабый, средний предмет | E = 2.83 | E = 2.33 |

Середина шкалы при этом сохраняется: на `s = d` оценки 3 и 4 остаются
самыми вероятными (по 0.41), гейт лишь делает модель решительнее в
промежуточных случаях.

### Чего от модели ждём

| s | d | сценарий | ожидаемая оценка |
|---|---|---|---|
| 0 | 1 | слабый студент, сложный предмет | 2 |
| 0.5 | 0.5 | средний, средний | 3–4 |
| 1 | 0 | сильный, лёгкий | 5 |
| 0 | 0 | слабый, лёгкий | 3–4 (точно не 5) |
| 1 | 1 | сильный, сложный | 3–4 (точно не 5) |

Проверка всех трёх формул по этим точкам — в
[`notebooks/model_comparison.ipynb`](notebooks/model_comparison.ipynb).
Коротко: `legacy_sd` и `sigmoid` дают ожидаемое поведение, `current` тянет
среднюю точку к 4–5 и «слипает» углы `(0,0)` и `(1,1)`.

## Chi-square приор на сложность

Плоский `Beta(2, 2)` для всех предметов игнорирует то, что видно сразу: у
«сложного» предмета распределение оценок другой формы, чем у «лёгкого».
`chi_square_difficulty` меряет χ²-расстояние от эмпирического распределения
оценок предмета до двух эталонов и возвращает число из `[0, 1]`:

```
score = χ²(эмпирика, эталон_лёгкого) / (χ²(…лёгкого) + χ²(…сложного))
```

Оно и становится центром `Beta`-приора для этого предмета.
Подбор эталонов — в [`notebooks/chi_square.ipynb`](notebooks/chi_square.ipynb).

`data/grades_sem*.csv` — обезличенная выгрузка: строки индексированы порядковым

## Валидация: какая конфигурация лучше описывает данные

Сходимость говорит только о том, что сэмплер отработал корректно. Вопрос
«какая из шести конфигураций ближе к реальности» решает `scripts/validate.py`:
PSIS-LOO (предсказательная способность с поправкой на сложность) и posterior
predictive check. LOO считается отдельно по каждому семестру — сравнивать
можно только модели, обученные на одних наблюдениях.

Рейтинг совпал в обоих семестрах (`results/loo_compare_sem{1,2}.csv`):

| конфигурация | elpd_loo сем 1 | elpd_loo сем 2 | место |
|---|---|---|---|
| `nocond` + `current` | −626.6 | −978.2 | 1 |
| `nocond` + `sigmoid` | −631.7 | −993.8 | 2 |
| `cond` + `current` | −655.8 | −1005.6 | 3 |
| `nocond` + `legacy_sd` | −663.5 | −1016.4 | 4–5 |
| `cond` + `legacy_sd` | −664.4 | −1014.0 | 4–5 |
| `cond` + `sigmoid` | −664.5 | −1019.3 | 6 |

**Главный вывод: гейт ухудшает предсказательную способность.** Все три
конфигурации с `cond` проигрывают своим аналогам без гейта, отрыв 29–41 elpd
при `dse` 5–9, то есть около 5 стандартных ошибок — это не шум. Между
`current` и `sigmoid` без гейта разница 5.1 при `dse` 4.4 (семестр 1):
статистически неразличимо, LOO не выбирает между формулами `ratio`.

### Posterior predictive check: провал, общий для всех конфигураций

Из постериора разыгрываются новые комплекты оценок, и их распределение
сравнивается с фактическим (`results/ppc_summary.csv`,
`results/plots/ppc_sem{1,2}.png`). Результат честнее назвать плохим:
у дефолтной конфигурации фактическая доля попадает в 94% интервал модели
**в 2 случаях из 8**.

Семестр 1, отклонение модели от факта в процентных пунктах:

| оценка | факт | `nocond`+`sigmoid` | `cond`+`sigmoid` |
|---|---|---|---|
| 2 | 2.0% | 5.1% (+3.1) | 7.8% (+5.8) |
| 3 | 32.5% | 23.4% (−9.1) | 22.1% (−10.5) |
| 4 | 25.7% | 31.8% (+6.1) | 26.6% (+0.9) |
| 5 | 39.8% | 39.7% (−0.1) | 43.5% (+3.7) |
| **сумма \|откл\|** | | **18.4 п.п.** | **21.0 п.п.** |

Счётчик попаданий вводит в заблуждение: `cond` случайно попал по четвёркам,
но суммарно отклоняется сильнее. По семестру 2 конфигурации примерно вровень
(13.7 против 12.7 п.п.).

**Важнее другое: промах общий для всех шести вариантов.** Каждый занижает
долю троек на 6–10 п.п. и завышает долю двоек в 2–4 раза. Это не следствие
гейта и не следствие выбора `ratio` — это свойство самого семейства
`f_2..f_5`. С текущими константами (`(1−x)³` в числителе, `10x²` в
знаменателе) оно не воспроизводит форму «двоек почти нет, троек треть»,
характерную для реальных ведомостей.

Так что смена дефолта улучшает предсказание отдельных оценок, но не чинит
форму распределения. Подгонка констант `f`-семейства под наблюдаемые доли —
следующий содержательный шаг, и делать его нужно с этой же валидацией
в качестве критерия.

### Вторая метрика: точность на наблюдённых оценках

LOO оценивает предсказание вне выборки. Полезно посмотреть и на то, что
модель выдаёт непосредственно — те самые вероятности, которые печатает
`query.py`, с маргинализацией по постериору (`results/predictive_scores.csv`):

| сем | конфигурация | log_pred | MAE |
|---|---|---|---|
| 1 | `nocond` + `sigmoid` | **−0.754** | **0.424** |
| 1 | `nocond` + `current` | −0.771 | 0.446 |
| 2 | `nocond` + `sigmoid` | **−0.836** | **0.480** |
| 2 | `nocond` + `current` | −0.843 | 0.488 |

Порядок первых двух перевернулся относительно LOO. Это не противоречие,
а ровно то, о чём говорил `dse`: **данные не выбирают между `current` и
`sigmoid`** — разница в пределах шума, и знак зависит от метрики. При этом
у `current` в семестре 1 шестнадцать точек с Парето-k > 0.7 против трёх у
`sigmoid`, то есть его LOO-оценка ещё и менее надёжна.

Про гейт обе метрики согласны: `cond` проигрывает своему `nocond`-аналогу
в каждой паре и по LOO, и по log_pred.

**Итог.** Дефолт — `nocond` + `sigmoid`: он лучший по прямой предсказательной
метрике в обоих семестрах, статистически неотличим от лидера LOO, и при этом
не имеет смысловых дефектов `current` (`E[оценка] = 4.24` для среднего
студента на среднем предмете, слипание углов `(0,0)` и `(1,1)` — см.
[`model_comparison.ipynb`](notebooks/model_comparison.ipynb)).

Оговорка про надёжность LOO: у лидирующих конфигураций 6–16 наблюдений с
Парето-k > 0.7 (колонка `bad_pareto_k`), для них аппроксимация не
гарантирована. У `cond` + `legacy_sd` таких точек 1–2 — её оценка самая
надёжная, хотя по величине она в середине рейтинга.

## Сходимость

Проверяется `scripts/diagnostics.py`, результат — в `results/diagnostics.csv`.
Пороги: `r_hat ≤ 1.01`, `ESS ≥ 400`.

**Сошлись все 12 трасс из 12, дивергенций ноль.** Худший `r_hat` — 1.009,
худший ESS — 512.

Далось это не сразу, и цифры стоит воспроизводить теми же настройками:

| | настройки | результат |
|---|---|---|
| первый прогон | `draws=1000, tune=2000, target_accept=0.95` | 8 из 12 |
| второй | `draws=4000, tune=2000` | 11 из 12 |
| `sem2 · cond · sigmoid` отдельно | `draws=8000, tune=6000, target_accept=0.99` | 12 из 12 |

Сложнее всего сходится именно `sigmoid` — и по иронии это выбранный дефолт.
Страдает не способность студентов, а сложность предметов: параметров мало,
наблюдений на каждый много, постериор узкий и плохо перемешивается. Лечится
числом draws и tune, а не сменой модели — дивергенций не было ни разу ни в
одной конфигурации, то есть геометрия для NUTS нормальная.

Воспроизвести полностью:

```bash
python scripts/run_mcmc_chi_prior.py --draws 4000 --tune 2000 --chains 4 --cores 4
python scripts/run_mcmc_chi_prior.py --sem 2 --model cond --ratio sigmoid \
    --draws 8000 --tune 6000 --target-accept 0.99
python scripts/diagnostics.py
```
